# Architectural Gap Register

This document registers critical engineering gaps where none of the five audited repositories provide an adequate, ready-to-use implementation, necessitating original development and testing for Reel Engine v0.1.

---

## 1. High-Priority Gaps in Quality Enforcement & Infrastructure

| Gap ID | Area | Exact Description & Why Existing Repositories Fail | Required Reel Engine Solution | Severity / Risk |
|---|---|---|---|:---:|
| **GAP-01** | **Deterministic Blocking Gates Architecture** | Existing repos treat quality checks as advisory logs (e.g. OpenChatCut's `sceneQuality.ts:1` explicitly has no enforcement role, and mimic-mcp leaves checks to the agent's discretion). No repository implements a server-enforced blocking gate that programmatically halts the pipeline before composition when quality fails. | Implement a formal `Gatekeeper` service that evaluates 7 deterministic checks (duration match, zero exit code, safe area, reading dwell time, loudness, static limit, transition budget). The `compose()` tool literally refuses execution until all 7 gates pass with 0 errors. | **CRITICAL** |
| **GAP-02** | **Audio-Driven Integer-Frame Timeline Solver** | OpenMontage and short-video-maker use naive floating-point seconds (`duration = 3.5`), leading to rounding errors and cumulative A/V lip-sync drift over multiple scene cuts. OpenChatCut has complex NLE interchange timecodes but no automated speech-to-scene quantization solver. | Build an audio-master timing solver that ingests Whisper word timestamps, enforces integer frame boundaries (`round(time_s * fps)`), snaps cuts to speech phrase ends with tunable lead frames, and guarantees that `sum(scene_frames) == total_audio_frames`. | **CRITICAL** |
| **GAP-03** | **True Visual Change & Static Window Detection** | No audited codebase analyzes rendered video frames to verify whether the visible screen actually changed every 1.5–3.0 seconds. They only count metadata event tags in text files, meaning an agent can write a static scene with fake event tags and pass. | Implement a rendered-frame difference checker using FFmpeg `mpdecimate` or OpenCV frame subtraction over sliding windows. Rejects scenes where pixel variance remains below the motion threshold for longer than `max_static_s`. | **HIGH** |
| **GAP-04** | **Caption Reading Dwell Time Verification** | None of the audited repositories verify reading legibility against text length. Short-video-maker and OpenChatCut flash multi-line captions without checking if viewers have enough time to read them before the cut. | Implement deterministic CPS (characters-per-second) validator in the IR linter: `dwell_frames >= ceil((character_count / 18.0) * fps)`. Flags any text event or caption block that disappears prematurely. | **HIGH** |
| **GAP-05** | **Content-Addressed Multi-Tier Scene Caching** | While OpenMontage hashes raw downloaded assets (`lib/asset_cache.py`), no repository implements multi-tier invalidation for hybrid scene code. In existing repos, editing a single scene re-renders the entire video or risks using stale clips. | Implement content-addressed scene hashing: `hash = sha256(scene_ir_json + scene_code_file + style_tokens_json + audio_slice_bytes + renderer_version)`. Renders only cache misses. | **HIGH** |
| **GAP-06** | **Strict Phased MCP State Machine with Recovery** | All existing MCP servers expose unstructured tools that agents can call out-of-order (e.g. calling `render` before `plan`, or `compose` with missing scenes). None provide an authoritative `get_next_step()` tool to recover context after an agent crash. | Build an explicit finite state machine (FSM): `input -> transcribed -> planned -> authored -> rendered -> verified -> composed -> exported`. Enforce legal transitions and typed `next_step` messages. | **HIGH** |
| **GAP-07** | **Dual-Renderer Shared Token & Coordinate Bridge** | Remotion operates in CSS pixels (1080x1920) with web flexbox/grid layout, whereas Manim operates in normalized Cartesian coordinates (`[-4, 4]` or `[-7, 7]`) with 3D camera matrices. No audited repo bridges these two worlds. | Author a dual-renderer helper library: `reel-remotion-helpers` (npm) and `reel_manim_helpers` (pip) that map unified percentage coordinates (`x: 0..1, y: 0..1`), color hexes, and font sizes into identical visual dimensions. | **HIGH** |
| **GAP-08** | **Non-Destructive Post-Production Export Edit List** | All five repositories require a full re-render if the user or agent wants to reorder scenes, trim heads/tails, or mute an individual scene clip. | Implement an `edit` section in project state holding non-destructive cuts (`trim_in`, `trim_out`, `scene_order`, `enabled_flags`). Applied in Phase E via FFmpeg filtergraph concat without re-rendering clips. | **MEDIUM** |
| **GAP-09** | **Creative Self-Review Rubric Gate** | No repository requires an agent to evaluate its own work against a structured rubric before allowing final composition. Existing tools allow low-effort, generic prompts to pass unchecked. | Implement `submit_review(rubric)` tool enforcing scoring across Hook, One Idea, Pacing, Legibility, Motion, Send Moment, and Payoff. Blocks compose if any item is 0 or total score < minimum passing threshold. | **MEDIUM** |
